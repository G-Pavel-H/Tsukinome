# Plan — Issue #59: Add a formatDuration(ms) helper and use it in the run cost summary

> Generated by Tsukinome. The technical blueprint for the work, approved before any code.

## Summary

Add a new self-contained formatting utility module, `src/format.ts`, exporting `formatDuration(ms: number): string` that maps a millisecond count to a compact human-readable string with guarded handling of zero, negative, and non-finite input. Cover it with a dedicated Vitest unit suite mirroring the existing `test/llm/pricing.test.ts` style, then wire the run cost summary (`src/pipeline/cost.ts` `renderCostSummary`) to render its duration via `formatDuration` instead of raw milliseconds, matching the existing `formatUsd` helper idiom.

## Approach

The repo already keeps small pure formatting helpers as named exports next to their domain (e.g. `formatUsd` in `src/llm/pricing.ts`) and top-level single-purpose modules (`src/log.ts`, `src/config.ts`). Since duration formatting is cross-cutting and not LLM-specific, follow the top-level-module convention and add `src/format.ts` with a single exported pure function `formatDuration`, keeping ESM `.js` import specifiers consistent with the codebase. Implementation is a straight branch ladder ordered smallest-to-largest with explicit guards first: (1) `!Number.isFinite(ms)` → `"0ms"`; (2) `ms <= 0` → `"0ms"` (covers negative and negative zero); (3) `ms < 1000` → `` `${Math.round(ms)}ms` `` (round-half-up sub-second); (4) `ms < 60_000` → `` `${Math.floor(ms / 1000)}s` `` (truncate sub-second remainder, R12); (5) `ms < 3_600_000` → minutes `Math.floor(ms / 60_000)` and seconds `Math.floor((ms % 60_000) / 1000)` → `"Xm Ys"` (R13); (6) else hours `Math.floor(ms / 3_600_000)` and minutes `Math.floor((ms % 3_600_000) / 60_000)` → `"Xh Ym"`, dropping seconds. No new abstractions, config, or options — respecting the non-goals (no i18n, no sub-ms/above-hour units, no configurable precision). For R11/R14, update the run cost summary render so the duration value it surfaces passes through `formatDuration`; `renderCostSummary` gains an explicit millisecond duration input rendered via the helper (import from `../format.js`), and its single pipeline caller is updated to pass the already-measured run duration. This is the smallest change that makes the summary show human-readable durations without altering how durations are measured or stored.

- `src/format.ts` **(add)** — New self-contained utility module exporting the pure formatDuration(ms) helper.
- `test/format.test.ts` **(add)** — Unit suite covering every documented example and edge case (AC1–AC10).
- `src/pipeline/cost.ts` **(modify)** — Render the run cost summary duration via formatDuration instead of raw milliseconds (R11/R14).
- `test/pipeline/cost.test.ts` **(modify)** — Assert the cost summary shows the human-readable duration (e.g. '1m 5s') rather than raw ms (AC11).

## Contracts

- src/format.ts: export function formatDuration(ms: number): string — returns '0ms' for 0, negative, or non-finite input; '<n>ms' (round-half-up) under 1000ms; '<n>s' (floored) for 1000–59999ms; 'Xm Ys' (floored sub-units) for 60000–3599999ms; 'Xh Ym' (floored, seconds dropped) at or above 3600000ms.
- src/pipeline/cost.ts: renderCostSummary gains an explicit run-duration-in-milliseconds input whose displayed value is produced by formatDuration(durationMs); its pipeline caller passes the measured run duration.
