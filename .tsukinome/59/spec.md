# Spec — Issue #59: Add a formatDuration(ms) helper and use it in the run cost summary

**Type:** feature

> Generated by Tsukinome. This file is the source of truth for the work; edits here drive the build.

## Summary

Add a self-contained `formatDuration(ms: number): string` utility that converts a millisecond count into a compact, human-readable string (e.g. "820ms", "5s", "1m 5s", "1h 0m"), covering edge cases like zero, negative, and non-finite input. Ship it in a utility module with unit tests, and use it in the run cost summary so durations render in the human-readable form instead of raw milliseconds.

## Requirements

Each requirement is tagged with a confidence level (explicit / inferred / assumption / unknown).

- **R1** `[explicit]` A function `formatDuration(ms: number): string` exists in a small, self-contained utility module.
- **R2** `[explicit]` For input of exactly 0, the function returns "0ms".
- **R3** `[explicit]` For input greater than 0 and under 1000ms, the function returns the whole-millisecond count followed by "ms" (e.g. 820 → "820ms").
- **R4** `[explicit]` Sub-second (under 1000ms) input is rounded to the nearest whole millisecond before formatting.
- **R5** `[explicit]` For input at or above 1000ms and under 60000ms, the function returns whole seconds followed by "s" (e.g. 5000 → "5s").
- **R6** `[explicit]` For input at or above 60000ms and under 3600000ms, the function returns minutes and seconds as "Xm Ys" (e.g. 65000 → "1m 5s").
- **R7** `[explicit]` For input at or above 3600000ms, the function returns hours and minutes as "Xh Ym", dropping seconds (e.g. 3600000 → "1h 0m").
- **R8** `[explicit]` Negative input returns "0ms".
- **R9** `[explicit]` Non-finite input (NaN, Infinity, -Infinity) returns "0ms".
- **R10** `[explicit]` The utility module is accompanied by unit tests covering the documented example inputs and edge cases.
- **R11** `[explicit]` The run cost summary displays durations using `formatDuration` instead of raw milliseconds.
- **R12** `[assumption]` At the seconds scale (1000ms–59999ms) any sub-second remainder is dropped by rounding down to whole seconds (e.g. 5900 → "5s").
- **R13** `[assumption]` At the minute scale, seconds are computed as whole seconds within the minute (remainder truncated), and at the hour scale minutes are whole minutes within the hour (remainder truncated).
- **R14** `[inferred]` All existing display sites that currently render raw millisecond durations are updated to use `formatDuration`.

## Non-Goals

- Adding localization or internationalization of the duration strings.
- Supporting units below milliseconds (microseconds/nanoseconds) or above hours (days/weeks).
- Providing a configurable output format or precision options.
- Changing how durations are measured or stored — only how they are displayed.

## Edge Cases

- Exactly 0ms → "0ms".
- Boundary at 999 vs 1000 (ms scale vs seconds scale).
- Boundary at 59999 vs 60000 (seconds vs minutes) and 3599999 vs 3600000 (minutes vs hours).
- Sub-second fractional values requiring rounding (e.g. 0.4 → "0ms", 0.6 → "1ms").
- Negative values including negative zero.
- Non-finite values: NaN, Infinity, -Infinity.
- Whole-hour and whole-minute values where a sub-unit is zero (e.g. 3600000 → "1h 0m", 60000 → "1m 0s").
- Very large values (e.g. multi-hour durations) rendering as "Xh Ym".

## Assumptions

- At the seconds scale (1000–59999ms) sub-second remainders are dropped by rounding down to whole seconds (e.g. 5900 → "5s").
- At the minute and hour scales, the smaller sub-unit (seconds within a minute, minutes within an hour) is truncated rather than rounded.
- All existing raw-millisecond display sites are updated, not just the cost summary, per the issue's 'apply wherever durations are shown'.
- Rounding at the sub-second scale uses standard round-half-up (e.g. 0.5 → "1ms").
