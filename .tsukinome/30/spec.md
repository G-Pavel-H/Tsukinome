# Spec — Issue #30: Add formatDuration helper for human-readable run time display

**Type:** feature

> Generated by Tsukinome. This file is the source of truth for the work; edits here drive the build.

## Summary

Add a self-contained utility function formatDuration(ms) that converts a millisecond count into a compact, human-readable string with scale-specific formatting rules, and use it to display run durations in the cost summary instead of raw milliseconds.

## Requirements

Each requirement is tagged with a confidence level (explicit / inferred / assumption / unknown).

- **R1** `[explicit]` A function formatDuration accepting a number of milliseconds and returning a string must exist in a small utility module.
- **R2** `[explicit]` For input 0, the function returns "0ms".
- **R3** `[explicit]` For values under one second (0 < ms < 1000), the function returns the value in whole milliseconds with an "ms" suffix (e.g., 820 → "820ms").
- **R4** `[explicit]` Sub-second millisecond values are rounded to whole milliseconds before formatting.
- **R5** `[explicit]` For values from one second up to (but under) one minute, the function returns whole seconds with an "s" suffix (e.g., 5000 → "5s").
- **R6** `[explicit]` For values from one minute up to (but under) one hour, the function returns minutes and seconds as "Xm Ys" (e.g., 65000 → "1m 5s").
- **R7** `[explicit]` For values of one hour or more, the function returns hours and minutes as "Xh Ym", dropping seconds (e.g., 3600000 → "1h 0m").
- **R8** `[explicit]` For negative or non-finite input (NaN, Infinity, -Infinity), the function returns "0ms".
- **R9** `[explicit]` The utility module has unit tests covering the specified behaviours.
- **R10** `[explicit]` The cost summary display uses formatDuration to render durations instead of raw milliseconds.
- **R11** `[inferred]` Seconds/minutes components are computed by truncating (flooring) the appropriate units so that, e.g., 65000ms yields 1m 5s and 5999ms at second scale yields 5s.
- **R12** `[inferred]` Second, minute, and hour components are displayed as integers without leading zeros (e.g., "5s", not "05s").

## Acceptance Criteria

### AC1

- **Given** a duration of 0 milliseconds
- **When** formatDuration(0) is called
- **Then** it returns "0ms"

### AC2

- **Given** a duration of 820 milliseconds
- **When** formatDuration(820) is called
- **Then** it returns "820ms"

### AC3

- **Given** a duration of 5000 milliseconds
- **When** formatDuration(5000) is called
- **Then** it returns "5s"

### AC4

- **Given** a duration of 65000 milliseconds
- **When** formatDuration(65000) is called
- **Then** it returns "1m 5s"

### AC5

- **Given** a duration of 3600000 milliseconds
- **When** formatDuration(3600000) is called
- **Then** it returns "1h 0m"

### AC6

- **Given** a fractional sub-second value such as 820.6
- **When** formatDuration(820.6) is called
- **Then** it returns "821ms" (rounded to whole milliseconds)

### AC7

- **Given** a negative value such as -5
- **When** formatDuration(-5) is called
- **Then** it returns "0ms"

### AC8

- **Given** a non-finite value such as NaN or Infinity
- **When** formatDuration is called with it
- **Then** it returns "0ms"

### AC9

- **Given** a run whose duration is available in the cost summary
- **When** the cost summary is rendered
- **Then** the duration is displayed using formatDuration output rather than raw milliseconds

## Non-Goals

- Localization or internationalization of unit labels.
- Supporting units larger than hours (days, weeks).
- Configurable precision or format options via parameters.
- Changing the underlying storage or measurement of durations.

## Edge Cases

- Exactly 1000ms (boundary between ms and seconds → "1s").
- Exactly 60000ms (boundary between seconds and minutes → "1m 0s").
- Exactly 3600000ms (boundary into hours → "1h 0m").
- Fractional millisecond input requiring rounding.
- Very large values (multiple hours).
- Value of 0.4ms that rounds down to 0 (should render "0ms").
- Negative zero (-0).

## Assumptions

- Minute/second/hour components are computed by flooring the respective units.
- Numeric components are rendered as integers without leading zeros or padding.
